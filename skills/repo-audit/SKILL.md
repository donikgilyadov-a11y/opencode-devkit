# Аудит репозиториев

Инструменты плагина `audit-tools` работают **только на чтение**: не меняют файлы, не запускают сборки,
не обращаются к сети. Это безопасно для чужих и больших репозиториев.

## Инструменты

- `audit.quick({ directory })` — короткая сводка: файлы, размер, ветка, README, риски.
- `audit.repo({ directory, name? })` — полный отчёт, сохраняется в `brain/reports/repo-audit-<name>-YYYY-MM-DD.md`.

CLI без агента:

```powershell
node "%USERPROFILE%\Desktop\opencode-boost\scripts\repo-audit.js" "<папка>"
node "%USERPROFILE%\Desktop\opencode-boost\scripts\repo-audit.js" "<папка>" --json --no-save
```

## Что проверяется

- Git: ветка, origin, последний коммит, число изменений в рабочем дереве.
- Файлы: количество, размер, расширения; пропускаются `node_modules`, `.git`, `dist`, `build`, `coverage`.
- Признаки: README, AGENTS.md, docs, wiki, тесты, CI, lockfile, tsconfig, .env.example, Docker, k8s, LICENSE.
- `package.json`: имя, версия, скрипты, число зависимостей и workspaces.
- Маркеры `TODO/FIXME/HACK/XXX` и похожие на секреты строки. **Значения секретов не сохраняются** — только путь и строка.

## Правила

1. Никогда не меняй проверяемую папку: никаких install/build/format/commit без отдельного явного запроса.
2. Если пользователь задал границу «не трогать основной репозиторий», соблюдай её: аудит — только чтение.
3. Сначала `audit.quick`, затем при необходимости полный `audit.repo`.
4. Важные выводы дублируй в мозг: `brain.save(topic, text, long?)`.
5. Отчёт — стартовая точка, не истина в последней инстанции: уточняй у пользователя перед действиями.
